# M8 真实 51 页 · 看图比对报告

> 目的：用多模态能力**直接读原始 PDF 的纸面事实**，与真实 e2e 落库的 findings 逐条比对，
> 找出「工具结论」与「纸面事实」的差距，并据此定位规则层缺陷。
> 样本：`samples/丝裂霉素提取批记录.pdf`（51 页，含大量手写）。
> 首轮基线：job `a5284ca3-47b`（paddle，11:47–12:06，落库 395 条）。
> 比对日期：2026-09-14。

## 一、方法与坑

1. **页面方向逐页不同，不能一刀切**。原 PDF 每页是一张 3000×4000 的整页栅格
   （PDF 声明 72dpi，相对实际纸张约 360dpi）。p08 需 `set_rotation(90)` 转正，
   p19 需要另一角度——按页探测，否则坐标映射错位、读到空白。
2. **最高保真读法：直接抽嵌入栅格**，绕开页面旋转与重采样：
   ```python
   xref = page.get_images(full=True)[0][0]
   open("raw_pNN.jpeg", "wb").write(doc.extract_image(xref)["image"])
   ```
   得到的就是扫描原图（3000×4000）。随后按像素裁切 + LANCZOS 放大 3~5×，
   手写数字与小数点均可辨认（脚本：`devlogs/_m8_render.py`）。
3. 与 DB 的 `findings`（`source`/`severity`/`type`/`description`）逐条对照；
   必要时回查 `page_cache.raw_html`（OCR 原文）与 `structured_json` 定位误差层级。

> 工具链核查的价值在于：**先把"纸面真值"钉死，再判断工具是"误报""漏报"还是"值失真"**。

## 三、四类差距与处置

### 1) `±` 被 OCR 丢成空格（p08 温度，21 条误报）

- 印版 `15±5 ℃` → OCR `15 5°C` → LLM 结构化规范化为 `15-5°C`
- 旧解析器解出反向区间 `between(15,5)`（左界>右界，恒假）→ 7 时点 × 3 温度列 = **21 条**
- **修复**（`core/rules/parsing.py::_parse_spec`）：支持 `±` 形式；支持空格 `A B`
  （仅 `|B|<|A|` 才按 `A±B`，防 `10 20` 误读）；**反向区间按 `A±B` 重建**（`A-B, A+B`）。

### 2) 小数点被 OCR 丢掉（p08 进料压力，7 条 warning + 1 条 critical）

- 手写 `4.6` → OCR `46`；规格 `3.0-5.0 bar` → 7 条 rule warning + 1 条 llm_page critical
- 同页其余压力 2~4 bar，TFF 工艺上 46 bar 不可能 → 真值 `4.6`
- **修复**：`_decimal_loss_factor` 软化，**两判据同时成立**才命中——
  ① 实测值本身不含小数点（丢点后数字串不变：`4.6`→`46`；自带小数点的 `45.6` 不算）；
  ② 超差倍数 ≈10×/100×（比值容差 `0.6~1.7`）。
  命中后降级 `info` + "疑似 OCR 丢失小数点，请对照 PDF 原页人工核对"（**表面化，不静默丢弃**）。
- **反例保护（回归门禁抓到过）**：`25 vs ≤5.0 ℃`（比值仅 5）、`45.6 vs 0~5 ℃`（自带小数点）
  必须维持 `warning` 铁口——首版软化过宽导致 2 项既有测试回归，补量级判据后修复。

### 3) LLM 自报超差无复核（p09 压力，7 条 critical）

- LLM 把 `<0.3 MPa` 当下限 → `0.16 MPa 超出规格 <0.3 MPa` × 7（critical）；
  数值上 `0.16 < 0.3` 全部合规，纯误报；**规则层从未产出此结论**
- **修复**：新增 `core/rules/spec_guard.py`——LLM 自报 `param_out_of_spec` 一律用
  **规则层同一解析器**复核；命中三元组状态全为 `in`/`soft` 才剔除；
  定位不到、不可判、符号存疑一律保留（**fail-closed**）。
- **踩到的坑**：结构化列名 `T2101a_压力`（下划线）与 LLM 文案 `T2101a 压力`（空格）
  分隔符不一致 → 原样子串匹配漏配 → 误报被 fail-closed 保留。
  加 `_norm`（去空白/下划线/连字符/括号 + 小写）后，p09 7 条被正确剔除。

### 4) 真空度/负压符号约定未 fail-closed（6 处改判人工）

- 规格 `≤0.08 MPa` × 负表压实测（`-0.068 ~ -0.096`）→ 数值比较恒真，**真实偏差被静默放过**
- **修复**：`_sign_convention_uncertain`（负实测值 × 印版正限值）命中即降级
  `spec_unverifiable` 交人工，不再静默判合规。

**误报消除盘点（按首轮落库数据精确核对）**

| 页 | 消除条数 | 其中 critical |
|---|---|---|
| p08 温度（`±` 丢失） | 21 | 0 |
| p08 进料压力（丢小数点） | 8 | 1（llm_page） |
| p09 压力（LLM 方向错） | 7 | 7（llm_page） |

### 5) 值失真（p19）—— 结论对、数据错，待产品化

`97.0%` 被 OCR 读成 `49.0%`；结论方向正确（确属不合格），但报告中的**实测值失真**，
GMP 复核会被误导。属另一性质：不是误报，而是"结论对、数据错"。
**建议**（未实现）：对低置信度（手写）实测值在界面显式标注"值未经确认"。

## 四、未决项（已定位，未修 —— 归因抽取质量，非解析器缺陷）

根因已进一步收敛：多数是 **OCR 把相邻单元格粘进同一个 `<td>`**，LLM 再从粘连串里
切出"看起来合法"的数字。这类错误**规则层与 LLM 层会被同时误报**，任何基于
"规格 vs 实测"的复核都无法发现（规格对、数字也"像真的"）。

| 页 | 现象 | 根因证据 |
|---|---|---|
| p6 | 实测写成 `"70 L 6.88"`（两格合并）→ 取 70 判超差，真值 6.88 合规 | `page_cache.raw_html` 粘连 |
| p9 | `本批树脂使用次数` 报 `417`，真值 `17` | OCR 原文为 `A000626-221201/417 次`（批次号尾部 `/4` 与 `17` 粘连） |
| p10/p16 | 把工艺正文 `850 kg` 当成 `氯化钠用量` 规格 | 非规格文本误作规格 |
| p18/p39 | 把清场检查项当规格判超差 | 检查项误作参数 |
| p22 | `流速 141.406` vs `1.0~1.5`（同页另有 `1.401` 合规读数） | 小数点错位/串列 |
| p2/p10/p19 | 手写年份 `2015` vs 印版 `2025`（封面明确印 2025年01月） | 手写年份位数辨识不可靠 |
| 多处 | 仅有"时:分"的时点被锚定到**当天**日期，进而产出 `signature_time_anomaly` | 日期缺省填充策略 |

**为什么不立刻加启发式软化**：以上都属"数字本身即错"，软化规则一旦过宽就会
**抑制真实超差**（fail-closed 原则要求宁可多报交人工）。且 `_decimal_loss_factor`
的教训已证明——软化必须有可机检的强判据。→ 留作后续专项（T-D），
方向为：抽取后校验（要求数字 token 与相邻文本有分隔符）、手写值置信度标注。
