# 趋势筛查（OOT）可行性评估

> M6 / T6.5 —— 对标宝软 EIOS 的"参数未超限但偏离历史区间"能力，评估**是否做、
> 何时做、怎么做**。
>
> 实测数据：`python scripts/eval_trend_basis.py --json out.json`（只读打开真实库）
> 结论一句话：**需求成立、依据明确，但当前数据前提不满足 → v1.1 不做，先做
> "数据沉淀"这一半。**

---

## 1. 结论

| 维度 | 判定 |
|---|---|
| 业务价值 | **高**。GMP 对"趋势"有明确条文要求，且 OOT 与 OOS 是两件事，现有 22 条规则**全部是批内判据**，没有任何跨批能力 |
| 法规定位 | **有据**。见 §2 的逐条引用（趋势分析、异常趋势调查、统计学方法） |
| 数据前提 | **不满足**。真实库中**只有 1 个真实批次**；参数身份标识 92 个变体对应实质 1 个产品（自由文本未归一）；53% 的参数声明了规格，其中仅 57% 可机械解析 |
| 结论 | **v1.1 不做**。列入 v1.2 首个候选；现在就做 §5 阶段 0（测量序列结构化沉淀），因其低成本、无 UI、无 schema 破坏性变更，且不做则 v1.2 也无从开始 |
| 不做的最强理由 | 单批次**无法标定阈值**，验收项无法证伪 —— 写"已实现趋势筛查"会是不可复核的断言。假阳性还会直接侵蚀 M2 刚刚建立的复核信任 |

---

## 2. 需求与依据（为什么值得做）

**概念区分**（这是它存在的理由）：

- **OOS（Out of Specification）**：值超出**规格范围** → 已由 R3 `param_out_of_spec` 覆盖。
- **OOT（Out of Trend）**：值**仍在规格内**，但偏离该参数的历史分布 → **当前完全未覆盖**。
  法规要求对"异常趋势"调查，而不仅是对超规格调查。

**GMP 依据**（引自内置知识库，条目 id 可点开核对原文）：

| 依据 | 条文 | 引用要点 |
|---|---|---|
| GMP 2010 第二百三十五条 | `gmp2010-235` | "考察批次数和检验频次应当能够获得**足够的数据，以供趋势分析**" —— **法规本身要求多批次数据**，直接构成当前的数据前提 |
| GMP 2010 第二百三十八条 | `gmp2010-238` | "应当对不符合质量标准的结果或**重要的异常趋势**进行调查" —— OOT 是法定调查触发项 |
| GMP 2010 第二百五十三条(一) | `gmp2010-253` | 分析"工艺性能和质量监测**趋势**……**必要时应当采用适当的统计学方法**" —— 统计阈值（如 ±3σ）有法源 |
| GMP 2010 第二百六十六条 | `gmp2010-266` | 每年按品种做**产品质量回顾分析**、"及时发现不良趋势"、"考虑以往回顾分析的**历史数据**" —— 趋势分析的主战场是年度回顾 |
| 确认与验证附录第二十九条 | `gmp2010_annex_vv-29` | 持续工艺确认（CPV）"必要时应当使用**统计工具**进行数据分析，以确认工艺处于受控状态" |
| GMP 2010 第二百五十二条 | `gmp2010-252` | 对"工艺性能和质量监测**趋势**"等进行调查并采取 CAPA |

即：**这不是"锦上添花的功能"，而是法规明确要求、当前产品结构上缺失的一类检查。**

---

## 3. 数据基础实测（能不能做）

命令：`python scripts/eval_trend_basis.py`（只读 `data/pharma.db`，实测非推测）

### Q1 是否存在"同一产品/工序"的多批次可比样本？

| 指标 | 实测 |
|---|---|
| 库中 job 总数 | 23 |
| 按文件名 | `51pages*.pdf` 系列 10 个、`丝裂霉素提取批记录.pdf` 3 个、其余为测试小样 |
| 含产品/文件编号标识的 job | 14 |
| **不同**产品/编号标识总数 | **92** |
| 出现在 ≥2 个 job 的标识 | 46 |

**判读**：46 这个数字**不能读成"有 46 组多批次样本"**。核实文件编号后可确认：
所有这些 51 页 job 都是**同一份批记录**（丝裂霉素提取，批号 112701，文件编号
`H3-MPD-10133-R20…`），只是开发期反复重跑。92 个"不同标识"实际指向实质 1 个产品 ——
差异来自全角/半角括号、空格、尾部"(及系列文件)"等**纯文本变体**。

→ **真实批次样本数 = 1。趋势筛查的输入序列长度为 1，无法成立。**

### Q2 参数名 / 测量列名能否作序列主键？

| 指标 | 实测 |
|---|---|
| 参数出现次数 | 3015 |
| **不同**参数名 | 510 |
| 只出现 1 次的参数名 | 188（**37%**） |
| **不同**测量列名 | 159 |
| 高频测量列 | `T2101a_流速` / `T2101a_压力` … 各 **112** 次；`温度` 102；`P1/P2/P3` 84 |

**判读**：参数名（`parameters[].name`）以自然语言短句为主（"状态标志使用是否正确"
"地面是否干净"），37% 只出现一次 → **不能直接当序列主键**。
但**测量列名**（`measurements[].values` 的键，如 `T2101a_流速`）来自**印刷表格表头**，
半结构化、重复率高（同一模板每页复现）→ **是可行主键，但需要一张归一化映射**
（`T2101a_流速` vs `T2101a 流速` vs `T-2101A/流速`）。

### Q3 `spec_range` 可机械解析率（能否靠规格判"偏离"）？

| 指标 | 实测 |
|---|---|
| 声明了 `spec_range` 的参数 | 1592 / 3015（**53%**） |
| 其中含数字（可解析） | 915（**57%**） |
| 即可机械解析者占全部参数 | **30%** |

**判读**：**不能**依赖规格判定 OOT —— 70% 的参数要么没写规格、要么是
"适宜"/"符合规定"这类不可解析表述。OOT 必须建立在**实测值序列**上
（历史均值/中位数 ± k·σ 或 %偏离），这也正好与第二百五十三条"适当的统计学方法"对齐。

## 4. 为什么不在 v1.1 做

1. **验收不可证伪**：只有 1 个真实批次，任何阈值都无从标定，"检出率/误报率"无法测量。
   按本项目"实证驱动"纪律，写一个无法用地面真值校验的能力等于没有 `release_gate`
   的绿灯 —— 不合格。
2. **需要新增持久化维度**：跨批序列要有稳定的 `(产品, 工序, 参数)` 键与逐批值，
   当前 schema（`jobs` / `page_cache` / `findings`）没有该维度，属 **schema 变更 +
   数据迁移 + 历史数据回填策略**，不是 M6 这种"SSE 优化 + 对标落地"的量级。
3. **假阳性代价高**：M2 的核心成果是把复核者从噪声里救出来（F1 = 1.0、净增价值
   已量化）。一个标定不足的趋势屏会在规格内正常波动上大量报警，**反向破坏**该成果；
   在 GMP 场景，复核者对"狼来了"的耐受度极低。
4. **前置条件被法规自己写明**：第二百三十五条要求"批次数……足以供趋势分析"。
   在数据量达标前实现该功能，属于**明知前提不满足仍上线**。

## 5. v1.2 落地路径（分阶段 + 可证伪准入）

### 阶段 0 —— 现在就做：测量序列结构化沉淀（低成本、无 UI、可回滚）

- 在分析完成时，把每页 `measurements[].values` / `parameters[]` 的
  **归一化键 + 值 + 单位 + `value_source` + 批号 + 页码**写入一张派生表
  `measurement_series`（只增不改，`PRAGMA user_version` 升版）。
- 同时落 `page_info.batch_no` / `production_date` / `file_code` 的**原始文本**，
  为阶段 1 的归一化留证据（先存原文，不急着归一到错）。
- 价值：**今天不落，明天无法补**。且这张表本身就能支撑"单批次内同参数一致性"
  （同批 112 次 `T2101a_流速` 是否自洽）这类立即可用的检查。
- 门禁：新增 `series_ingest` 结构检查 + 单测（用合成结构化页断言写入行数与键）。

### 阶段 1 —— 身份归一化

- 产品/工序键：`(归一化 product_code, 工序号)`。`file_code` 本身是稳定编号
  （`H3-MPD-10133-R20`），优先用它而不是 `title` 文本。
- 参数键：测量列名归一化表（去空格/统一全半角/统一大小写/别名合并），
  以配置文件维护并纳入机检，规则同 M5 的 `TYPE_QUERIES` 纪律。
- 目标指标（可机检）：高频列名归一化后**同键率 ≥ 90%**。

### 阶段 2 —— 屏幕规则 + 阈值标定

- 判据草案：同 `(产品, 工序, 参数)` 的历史序列 ≥ N 批，
  实测值偏离历史中位数 > k × MAD（用 MAD 而非 σ，抗离群）；
  或 Western Electric / 连续 7 点单侧等简单规则。
- 输出：**新增 finding 类型 `trend_deviation`（severity 上限 `warning`，绝不上 `critical`）**，
  走 M4 的六面同步（`CANONICAL_TYPES` / `zh_map` / `GMP_BASIS_MAP` / `TYPE_QUERIES` /
  前端双端），依据指向第二百三十五、二百三十八、二百五十三条。
- 阈值标定：用真实多批次数据扫描 N/k，报告 P/R/F1（复用 `scripts/eval_findings.py` 口径）。

### 准入条件（未满足前不进阶段 2）

- [ ] 同一 `(产品, 工序)` 至少有 **≥5 个真实批次**（不同批号，非同一 PDF 重跑）；
- [ ] 目标参数的列名归一化同键率 **≥90%**；
- [ ] 参与计算的值 **`value_source == "printed"`**（手写/未知一律排除，防 OCR 噪声入模）；
- [ ] 在一份**冻结**的多批数据集上给出 P/R/F1 与误报样例，且误报可解释。

## 6. 风险与边界（若将来实现）

| 风险 | 处置 |
|---|---|
| OCR/手写噪声进入序列 → 假趋势 | 只取 `value_source == "printed"`；`_ocr_low_conf_cols` 命中的页/列排除 |
| 单位不一致导致"偏离" | 单位参与键或用 `spec_unverifiable`（已存在的类型）标记不可换算者，不参与统计 |
| 把 OOT 说得比 OOS 严重 | 类型严重度上限 `warning`；报告中与 `param_out_of_spec`（OOS）分区展示，避免混淆 |
| 批次数不足时给出"趋势" | 低于最小样本数时**不出结论**并显式说明"N 批不足以判定趋势"（比沉默更安全） |
| 产品/工序误归一 → 跨产品比 | 归一化表变更需 diff + 复核；键取自 `file_code` 而非标题文本 |
