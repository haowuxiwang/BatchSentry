# 视觉交叉验证（模型视觉 × 系统产出）

> 目的：用"能直接看扫描件"的视觉能力，独立复核系统对真实批记录的判定，
> 量化"哪里准、哪里是噪音"，为降噪提供地面真值。
> 本轮样本：`丝裂霉素提取批记录.pdf`（51 页，138MB，Paddle 后端）。

## 1. 方法

1. 取已完成轮次 `0c5cfb00-897` 的 findings 与 `page_cache`（真实库，非合成）；
2. 按 findings 密度选页（page 8/19/24/39），从**原始 PDF** 渲染页面；
3. 逐页目视独立判读，再与系统产出逐条比对；
4. 对分歧点做证据溯源（OCR 原始产物 → bbox → 高倍渲染裁决）。

## 2. 关键发现

### 2.1 必须先解决"朝向"问题 —— 扫描件本身是旋转的

页面 `rect = 3000x4000`、`rotation = 0`，但**图像内容旋转了 90°**：
直接渲染得到的画面里，表格数据是竖排的；`set_rotation(270)` 再转 180° 后才得到
可正常阅读的版式。

**意义**：
- 佐证项目"朝向分类必须开启"的机检要求（`use_doc_orientation_classify` +
  逐页 `angle ∈ {0,90,180,270}`）不是可选项 —— 关掉它，该文档的 OCR 会整份错乱；
- 本轮我最初的多次坐标定位失败，根因正是**没把旋转算进去**（用未旋转坐标系
  去裁切，裁到的位置南辕北辙）。**做视觉复核必须先确认朝向，否则结论无效。**

### 2.2 系统判定为真命中的例子（视觉确认）

page 8「透过液 TMPs」列：规格印作 **1.5**，实测手写值 **0.90 / 1.00 / 1.10 / 1.10**。
目视确认**每个值都低于规格** → 系统报的
「TMPs 在所有时间点的实测值（0.90, 1.00, 1.10）均低于规格要求（1.5）」
是**真实缺陷，不是误报**。

同页另有多条规则命中（进料压力、时间格式、缺 QA 签名、跨页列不一致），
目视均能在页面上找到对应事实。

### 2.3 `46` vs `4.6`：一次 OCR 丢小数点（与既有结论独立吻合）

page 8「进料 压力(3.0-5.0bar)」列，7 个时间点的实测值 OCR 全部读作 **46**：

| 证据 | 内容 |
|---|---|
| 规格（印刷体，高可信） | `3.0-5.0 bar` |
| OCR 读数 | `46`（7 行一致） |
| 同页相邻列 | `3.5 / 3.4 / 35 / 29 / 2.6 / 5.8 / 0.90` —— 量级全部正常 |
| 物理合理性 | 超上限 9 倍不可能连续 7 小时稳定维持 |

**结论：`46` 实为 `4.6`（OCR 丢失小数点）**，缩放 0.1 后完全落在规格内。

⚠️ **本项目在 M8 阶段已用同样的视觉方法得出该结论**，并已把判据写进代码
（`core/rules/parsing.py::_decimal_loss_factor`，两判据：实测值不含小数点 +
超差倍数 ≈10×/100×；`core/rules/rule_spec.py:223-229` 据此降级为 `info` + 提示）。
**本轮视觉复核与代码注释中的既有结论独立吻合，互为交叉验证。**

## 3. 一次判断失误与更正（方法论教训）

**过程中的错误结论**：我最初从该轮 DB 读到这 7 条是 `severity=warning`
且描述里**没有**降级提示文案，据此判断"`_decimal_loss_factor` 没有生效"。

**更正依据（实证）**：

```text
# 直接用当前代码重放同一轮次的 page_cache
$ python scripts/replay_rules.py --job 0c5cfb00-897 --db <APPDATA>/PBC/data.db
  启用 M4: total=426  severity={'critical': 17, 'info': 212, 'warning': 197}
  关闭 M4: total=417  severity={'critical': 14, 'info': 210, 'warning': 193}
```

`info` 达 **210+ 条** —— 软化机制在当前代码里**确实在工作**。
真正的原因是**数据时效**：该轮次产生于 **2026-08-26**，早于这些降噪改动，
**旧产物不能代表当前代码的行为**。

**教训（已固化为纪律）**：
> 判定"当前代码是否有某行为"，**不能读历史轮的落地数据**，
> 只能用 `scripts/replay_rules.py` 在当前代码上重放。
> 历史 DB 里留着的是**当时的**代码产物。

这条与项目既有的"证据不可复算"纪律是同一族问题：历史产物只说明历史。

## 4. 仍待验证的降噪候选

比对中发现的现象（**需在真实 LLM 轮次上验证当前代码是否仍如此**，
`replay_rules.py` 会把 LLM 支路替换为空实现，故看不到）：

1. **跨 source 重复**：同一事实被 `rule`（逐时间点）、`llm_page`、`llm_cross`
   各报一次。在 page 8 的样本里，"进料压力 46 超标"一项共出现 **9 条**
   （7 条规则逐点 + 1 条 `llm_page` + 1 条 `llm_cross`，后两者描述文字完全相同）。
2. **矩阵逐点展开**：同一参数在 N 个时间点各报一条。
   在 GMP 审计语境下逐点留痕本身有价值，**不建议粗暴合并**；
   更合适的是"逐点保留 + 顶部聚合摘要"（与 R1 自指噪声的治理手法一致）。

## 5. 结论

- 视觉交叉验证**可行且有效**：能独立确认真实命中（TMPs）、独立复现 OCR 误读
  （4.6→46）、并暴露前置条件（朝向）。
- 系统在样本页上的**判定质量是可用的**：真命中可被目视证实，误报可被溯源到
  OCR 字符级错误且已有软化机制。
- **降噪应继续沿着"绑定可达证据"的方向**（区域锚、原始产物、重放），
  而不是靠放宽/收紧阈值。
