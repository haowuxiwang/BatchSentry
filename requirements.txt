# 运行时依赖 —— **精确锁定**（`==`），不是下界。
#
# 为什么锁死：本产品以 PyInstaller 冻结产物分发，"本机能跑、打包失败 / CI 挂"
# 这类漂移只会在发布时才暴露。锁定版本 = 让 CI、本地构建、发布包跑在同一组依赖上。
# 当前锁定值 = **门禁实测通过**的那一组（Python 3.11.9 / Windows）。
#
# 升级流程：改这里的版本号 → 本地装一遍 → 跑 `python scripts/release_gate.py`
# → 通过才提交。护栏 `tests/unit/test_declared_dependencies.py` 保证"源码里
# import 的包一定在清单里"（曾漏声明 markupsafe —— 只靠 Jinja2 的传递依赖撑着，
# Jinja2 一旦换实现就会炸）。
#
# 🔴 本机装依赖必须带这两个开关（2026-09-23 实测，升 Pillow 10→12 时踩到）：
#     CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000  python -m pip install ... < /dev/null --no-input
#   pip 会先**卸载**旧版（Pillow 上万文件）→ 撞上本环境的 safe-delete 批量删除闸门
#   → 无 TTY 时**不报错、只是不再输出**（日志 mtime 停滞十余分钟，而 `pip list`
#   显示"部分成功"，极具误导性），且**真的会删掉包**：中断后 `python-dotenv` 的
#   `dotenv/` 目录消失、只剩改名残留 `~ython_dotenv-*.dist-info`。
#   ⇒ 判断"到底装好没有"**一律以 `import` 为准**，不看 `pip list`。
#
# 未覆盖：**传递依赖**仍由 pip 解析（本文件只管直接依赖）。要完全复现，需
# pip-tools 之类的全量 lock；当前规模下先不做，但这一条是已知缺口，不是"已解决"。
